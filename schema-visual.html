Key Design Notes

  • Users PK = Email (NVARCHAR), not a surrogate int. All user-owned tables FK on Email.
  • Events use TPT inheritance: a base SmartStudy_Events row plus exactly one subtype row (Class / Task / Work / Personal), joined on EventId.
  • Tasks → Courses via CourseId FK with ON DELETE CASCADE. Tasks can also self-reference via ParentTaskId for sub-tasks.
  • UserCourses is the junction for N:N enrollment (composite PK Email + CourseId).
  • Friendships are normalized as Email1 < Email2 to avoid duplicate pairs.
  • SharedTasks is 1:1 with Tasks; SharedTaskMembers tracks per-partner response status and their CopyTaskId.
